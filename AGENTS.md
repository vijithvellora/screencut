# Repository Guidelines

## Project Structure & Module Organization

ScreenCut is a Python 3.10+ macOS desktop editor using PyQt6 and FFmpeg. `editor.py` coordinates workflows and starts the application. The `screencut/` package separates responsibilities:

- `models.py` and `projects.py`: editing state, validation, project persistence, and history.
- `media.py` and `processing.py`: asynchronous preview, cancelable workers, and FFmpeg graph construction.
- `ui.py` and `widgets.py`: layouts, canvas, timeline, and privacy-region controls.
- `annotations.py` and `annotation_panel.py`: shared annotation rendering and editing controls.

`tests/` contains generated-media, model, and offscreen Qt regressions. `README.md` documents user workflows. Styling lives in the UI modules; there is no dedicated asset directory.

## Build, Test, and Development Commands

Run from the repository root:

- `brew install ffmpeg`: install processing and metadata tools.
- `python3 -m venv .venv` then `source .venv/bin/activate`: create and activate the development environment.
- `python -m pip install -e '.[dev]'`: install the app and Ruff.
- `python editor.py` or `bash run_screencut.sh`: launch the editor.
- `QT_QPA_PLATFORM=offscreen python -m unittest discover -s tests -v`: run regressions.
- `ruff check .` and `ruff format --check .`: validate lint and formatting.
- `bash -n run_screencut.sh`: check launcher syntax.
- `python -m pip install '.[bundle]'` then `python create_app.py`: build `dist/ScreenCut.app` with PyInstaller.

## Coding Style & Naming Conventions

Use four spaces, `snake_case` functions, `PascalCase` classes, and uppercase constants. Preserve Qt override names such as `paintEvent`. Follow Ruff configuration in `pyproject.toml` and use dataclasses for editing state.

Keep state in `EditSession`. Store blur coordinates normalized to 0–1 and times in source-video seconds. Validate before saving/exporting. Keep processing off the UI thread and deliver worker updates through Qt signals; never forcibly terminate Qt threads.

## Testing Guidelines

Use `unittest` with `test_*.py` modules and descriptive `test_*` methods. No coverage percentage is enforced. Add regressions for behavior changes, especially timing, cancellation, project history, and switching sources. FFmpeg fixtures must be temporary and generated by tests. Inspect UI changes at 960×640 and larger sizes; verify actual exports for privacy changes.

## Commit & Pull Request Guidelines

Use focused, imperative subjects, following existing commits such as `Fix blur region pixelation and speed settings`. PRs should explain the problem, resulting behavior, validation, relevant issues, and screenshots for UI changes. Exclude generated videos, bundles, caches, and local environments.
